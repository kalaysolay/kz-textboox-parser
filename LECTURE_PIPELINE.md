# Пайплайн генерации лекций по учебникам (Damulab)

Генерация детских двуязычных (RU/KK) лекций по параграфам школьных учебников
Казахстана. Один прогон = одна тема = один файл `05-lecture.final.md`.

## Состав

Оркестратор и 4 роли — отдельные скиллы в `.cursor/skills/`:

| Скилл | Роль | Вход → выход |
|-------|------|--------------|
| `damulab-lecture-pipeline` (+ `contracts.md`) | оркестратор: brief, папка прогона, вызов ролей, финал | реплика → `00-brief.json` … `05-lecture.final.md` |
| `damulab-lecture-parser` | выжимка параграфа дословно из PDF | `00` + PDF + parsed v2 → `01-lecture-source.json` |
| `damulab-lecture-planner` | план лекции под возраст | `00` + `01` → `02-lecture-plan.json` |
| `damulab-lecture-generator` | текст лекции строго по плану и выжимке | `01` + `02` → `03-lecture.draft.md` |
| `damulab-lecture-reviewer` | проверка фактов, языка, паритет RU/KK | `01` + `02` + `03` → `04-lecture-review.json` + `05-lecture.final.md` |

Форматы всех артефактов — `.cursor/skills/damulab-lecture-pipeline/contracts.md`
(единственный источник истины, поля не выдумывать).

Рекомендованные модели по ролям (модель задаётся в вызове `Task`, не в скилле):

| Роль | Модель | Причина |
|------|--------|---------|
| parser | Mimo 2.6 | парсинг и OCR — его сильная сторона |
| planner | nemotron 3 Ultra | структура, педагогика |
| generator | GPT-5.6 или nemotron 3 Ultra | самый сильный текст, живое двуязычие |
| reviewer | nemotron 3 Ultra | строгость, фактчекинг |

## Структура каталогов

Зеркалит `sources/` и `parsed_outputs/` (предмет → класс):

```text
sources/<предмет>/<класс>/*.pdf              # исходники
parsed_outputs/<предмет>/<класс>/*.json      # распарсенные учебники
content/runs-lectures/
  _coverage.md                               # общий индекс всех лекций
  <предмет>/<класс>/
    _coverage.md                             # индекс лекций предмета+класса
    {topicSlug}-{YYYYMMDD-HHMM}/             # один прогон = одна тема
      00-brief.json                          # заказ (~2 КБ, коммитим)
      01-lecture-source.json                 # выжимка (~10 КБ, коммитим)
      02-lecture-plan.json                   # план (~5 КБ, коммитим)
      03-lecture.draft.md                    # черновик (~8 КБ, коммитим)
      04-lecture-review.json                 # разбор (~5 КБ, коммитим)
      05-lecture.final.md                    # ✅ результат (~8 КБ, коммитим)
      .local/pages/                          # PNG/TXT страниц (в .gitignore)
      logs/                                  # журналы ролей (в .gitignore)
```

Пример: `content/runs-lectures/математика/5 класс/koordinatnyy-luch-20260923-1030/`.

## Почему реализовано именно так

1. **Мультиагент вместо одного прохода.** Прямая генерация «прочитай PDF —
   напиши лекцию» даёт выдумки и потерю фактов. Разделение parser → planner →
   generator → reviewer даёт: специализацию (каждая роль делает одно дело),
   изоляцию reviewer (отдельный `Task`, не видит рассуждений автора — иначе
   проверка превращается в одобрение), воспроизводимость (состояние — в файлах
   `00–05`, следующий шаг читает файл, а не «помнит» чат). Та же схема уже
   проверена на `damulab-question-pipeline` (analyst → matrix → generator →
   reviewer → illustrator).

2. **Разные модели на разных этапах.** Парсинг (длинный OCR, таблицы, формулы,
   смешанные алфавиты) и генерация (живой детский текст на два языка) — разные
   нагрузки. Один сильный LLM на всё — переплата за токены парсинга и риск
   потерять точность извлечения. Поэтому: дешёвый и цепкий Mimo 2.6 на парсинге,
   самый сильный (GPT-5.6 / nemotron 3 Ultra) — на тексте лекции, строгий
   nemotron 3 Ultra — на проверке. Модель указывается в вызове `Task`
   оркестратором, замена модели не требует правок скиллов.

3. **Вложенность предмет → класс.** Плоская папка (`content/runs/` с 50+
   каталогами `math-5-...`) перестаёт читаться при добавлении второго предмета.
   Вложенность зеркалит уже принятую раскладку `sources/<предмет>/<класс>/` и
   `parsed_outputs/<предмет>/<класс>/`, поэтому парсер, человек и скрипты ищут
   файлы в одном и том же месте. Двухуровневый `_coverage.md` (корень + класс)
   даёт и общий обзор, и читаемый список на 200+ лекций.

4. **Тяжёлое — в `.local/`, в гит — только лёгкое.** Замер на живом прогоне
   вопросов: `pages/*.png` — 8,3 МБ, все JSON/MD вместе — ~50 КБ. Поэтому PNG/TXT
   страниц и журналы лежат в `.local/pages/` и `logs/` (оба в `.gitignore`),
   коммитятся только `00–05` (~30–50 КБ на прогон, экономия ×150). После приёмки
   `05` тяжёлое можно удалять — лекция не страдает, страницы перерендерятся.

5. **Жёсткий контроль языка.** Учебники — для детей, двуязычные, со смешанными
   алфавитами: казахская `і` (U+0456) vs латинская `i`, греческие α β γ θ μ π,
   спецсимволы ° ± × √ ≤. OCR без корпусов `kaz+rus+eng` (+ `ell` при формулах)
   молча превращает `θ` в `0`, а `μ` в `u`. Поэтому: parser смотрит PNG
   первично, фиксирует реально использованные корпуса в `ocrInfo.languages`,
   generator и reviewer проверяют смешение алфавитов внутри слов (`mixed_script`)
   пословно. Казахский — естественный школьный, не калька (`kk_calque`).

6. **Один повтор — потом стоп.** Повтор на роль — максимум один. Второй провал —
   сигнал чинить скилл или источник (запись в `content/pipeline-gaps.md`),
   а не «попробовать ещё». Разовые опечатки в gaps не идут.

## Как запустить

Предусловия: PDF лежит в `sources/<предмет>/<класс>/`, распарсенный JSON —
в `parsed_outputs/<предмет>/<класс>/`.

1. Попроси оркестратор, например:
   > Сгенерируй лекцию по теме «Координатный луч» для 5 класса математики.
   > Учебник: `parsed_outputs/математика/5 класс/math_aldamuratova_5grade_part1_parsed_v2.json`
2. Оркестратор уточнит недостающее (класс, казахское название темы, объём),
   заведёт `content/runs-lectures/<предмет>/<класс>/{topicSlug}-{время}/` и
   прогонит роли по порядку на рекомендованных моделях.
3. Результат: `05-lecture.final.md` в папке прогона + строка в `_coverage.md`.
   Отчёт — по-русски: готовность, что требует сверки с бумажным учебником
   (статус `ready_unverified`), что осталось на твоё решение.

Особые случаи: `blocked` (страницы нечитаемы / темы нет в учебнике) — стоп,
показываем похожие темы; `needs_rework` от reviewer — один повтор generator
по замечаниям из `04`, затем стоп. Коммит и загрузка в банк — только по явной
просьбе.
