# Парсер учебников — 1.0.0

Сначала прочитай [контракт](../../../content/parser-contract.md). Пользовательская
инструкция и журнал версий: [PARSER_GUIDE.md](../../../PARSER_GUIDE.md).
Инструменты находятся в `content/tools/`, не в игнорируемом `tools/pdf-extract/`.

## Один источник, одна подготовка

1. Явно указанный PDF (полный путь или файл из @) — основной вход. Не ищи замену
   по названию и не обходи репозиторий, если файл уже известен. @ — интерфейсная
   ссылка: передай утилите разрешённый путь, а не символ @.
2. Найди существующий job для этого PDF по `pdfSha256`; продолжи его. Иначе создай
   `ocr/jobs/<имя-книги>/`. Не смешивай разные книги в одном job.
3. Подготовь все страницы одной командой:
   `node content/tools/prepare-textbook.js --pdf "<PDF>" --out "<job>" --pages all --ocr --lang rus --workers 2 --visual always --progress`.
   Для казахского текста используй `kaz+rus`. OCR выполняется лишь там, где
   текстовый слой не пригоден; готовые результаты берутся из кэша. Не запускай
   глобально `--force-ocr`. Не подключай eng/ell/equ без конкретной необходимости
   и установленных моделей: дополнительные языки не гарантируют точность формул.
4. Проверь PNG обложки, оглавления и минимум двух пронумерованных страниц.
   Номера в индексе физические; в итоговых темах печатные. Сохрани
   `--set-offset N --mapping-evidence "<PDF N = печатная M; вторая проверка>"`
   повторной подготовкой того же job (кэш повторно не распознаётся).
   При непостоянном offset этот экспорт не применяй: сообщи ограничение,
   не угадывай номера.

## Структура без перепечатки

5. Читай страницы порциями: `select-textbook.js --index "<job>/index.json"
   --pages 9-16 --max-chars 16000 --out "<job>/packet.json"`.
   Прочитай packet; при `nextCursor` продолжи тот же диапазон с `--cursor N`.
   Пакет ограничен символами, не токенами. Не пропускай остаток.
6. Записывай компактный `<job>/structure.json` по контракту: метаданные,
   темы/правила/задания и ссылки на блоки. Не генерируй заново большие
   `full_text`/`question_text`/`statement`: сборщик копирует их из кэша.
   Сохраняй структуру после каждой порции; веди `<job>/progress.md`:
   готовые диапазоны, оставшиеся страницы, спорные места, следующая команда.
7. Сверяй по PNG все формулы, определения, даты, имена, таблицы, задания и ответы,
   а также подозрительный OCR, смешанные алфавиты и порядок колонок.
   Обычный повествовательный текст проверь выборкой по разным макетам;
   непроверенное оставь medium, не выдавай за high. Если выборка выявляет
   систематические ошибки, проверь весь затронутый макет/диапазон.
   `candidateUsable`, OCR-confidence и `allAvailable` — не доказательства точности.
   Исправления — только через `text_corrections` с исходной строкой и свидетельством;
   сырой кэш не редактируй. Для high внеси реально сверенные блоки в
   `verified_block_refs` с evidence; нельзя помечать всю книгу проверенной по одному примеру.
8. Учитывай каждый блок: содержимое темы/правило/задание либо
   `ignored_blocks` с причиной (водяной знак, номер страницы, служебный колонтитул).
   Пустые/графические/нечитаемые страницы — `page_dispositions` с объяснением.
   Изображения, которые несут условие задачи, нельзя просто исключить как мусор:
   запиши проблему/структурный прототип и ручную проверку. Границы тем определяй
   по книге, а не только по одинаковым заголовкам. Не теряй задания на стыке страниц.

## Сборка и проверка

9. `assemble-textbook.js --index "<job>/index.json" --plan "<job>/structure.json"
   --out "<parsed_outputs/.../book_parsed_v3.json>"`. Итог — один JSON с текстами
   и заданиями. Существующий итог не заменять без намеренного `--overwrite`.
10. `validate-textbook.js --parsed "<JSON>" --out "<job>/validation.json"`.
    Исправь конкретную ошибку и повтори сборку/проверку; не перезапускай весь OCR.
    Проверка структуры не заменяет сравнение с PDF.
11. `textbook-nav.js --parsed "<JSON>" --out "<job>/nav"` создаёт компактное
    оглавление и граф. Для последующей работы по теме добавь `--topic "<id/код>"`.
12. Сообщи путь JSON, покрытие страниц, количество тем/заданий, что проверено
    визуально и что остаётся сомнительным. Сохрани local metrics и progress.
    `log-stats.py` опционален для учёта, не является проверкой качества.

## Без лишних токенов

Не загружай весь PDF/OCR/итоговый JSON в контекст. Не читай файлы, которые только
что написал, без причины. Большие выборки делай утилитами; в ответе показывай
счётчики и пути. Не запускай независимых агентов на повторное чтение всей книги.
Повторное OCR — только для конкретной плохой страницы с изменёнными настройками.
Короткое задание, знак | и одинаковое начало двух вопросов сами по себе не ошибки.
Не выдумывай библиографию, переводы или дословные формулировки.
