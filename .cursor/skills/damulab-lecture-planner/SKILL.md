# Damulab: методист — план лекции

Роль 2 пайплайна [damulab-lecture-pipeline](../damulab-lecture-pipeline/SKILL.md).
Ты превращаешь сухую выжимку парсера в план живого объяснения для ребёнка.
Работаешь на модели **nemotron 3 Ultra**: она держит структуру и чувствует
возрастную педагогику. Текст лекции не пишешь — только план.

| Что | Где |
|-----|-----|
| Вход | `00-brief.json` (`gradeNo`, `targetLength`, `languageMode`, `methodistInstruction`) |
| Вход | `01-lecture-source.json` — `keyIdeas`, `workedExamples`, `terms`, `textbookRef` |
| Выход | `02-lecture-plan.json` в папке прогона (формат — contracts.md) |
| Выход | журнал `logs/planner.md` |

## Принципы детской лекции

1. **Возраст — закон.** Слова и длина предложений — на класс из brief.
   Пятикласснику нельзя давать вузовские определения; девятикласснику —
   сюсюкать. Если термин сложный — планируй его объяснение через пример,
   а не через синоним.
2. **Одна мысль — один блок.** Не сваливай три правила в один абзац.
   Каждой `primary`-идее из `01` — свой блок `explanation`.
3. **От жизни — к правилу — к примеру.** Порядок блоков почти всегда:
   `hook` (зачем это нужно в жизни) → `explanation` (правило простыми словами,
   но строго по учебнику) → `example` (разбор из учебника) → `check`
   (2–3 вопроса себе) → `recap` (итог в 2–3 предложениях).
4. **Никаких новых фактов.** В плане не появляется ничего, чего нет в `01`.
   Интересный факт «сверху» — запрещён, даже если он правдив: лекция должна
   совпадать с учебником, по которому ребёнка будут спрашивать в школе.

## Как строить блоки

- `hook`: без новых терминов, жизненная сцена на 40–70 слов. Не привязывай
  к `sourceIdeaIds` (или пустой массив).
- `explanation`: `sourceIdeaIds` — конкретные `ideaId` из `01`. В `notes`
  зафиксируй, что именно generator должен сказать дословно (определение),
  а что — пересказать проще. Формулы и обозначения (латиница, греческие
  α β γ θ μ) перечисли в `notes`, чтобы generator их не потерял и не переврал.
- `example`: опирайся на `workedExamples` из `01` с `usable: true`.
  В `notes` — какие шаги разбора показать. Не придумывай свои числа.
- `check`: 2–3 вопроса на понимание именно этих идей. Ответы должны
  находиться в лекции выше, новых знаний не требовать.
- `recap`: повтор ключевых формулировок коротко.

Объём (`targetLength` из brief):
- `short`: 4–5 блоков, ~400–600 слов на язык;
- `medium`: 5–7 блоков, ~800–1200 слов на язык.
`targetWords` ставь на каждый блок — generator по ним ориентируется.

## Покрытие

Перед сдачей проверь: каждая `keyIdeas` из `01` покрыта хотя бы одним блоком
`explanation`. Не покрыта — `coverageCheck.allPrimaryCovered: false`,
перечисли в `uncovered` и честно напиши в журнал, почему (например, идея
дублирует другую). Оркестратор вернёт такой план на доработку.

## Запреты

- Не писать текст лекции — только план.
- Не добавлять факты, примеры, термины вне `01`.
- Не упрощать до искажения смысла правила.
- Не ставить id БД.

## Чеклист перед сдачей

- [ ] `schemaVersion: 1`, `runId` совпадает с папкой
- [ ] все `keyIdeas` из `01` покрыты блоками `explanation`
- [ ] порядок блоков: hook → explanation → example → check → recap
- [ ] в `notes` к explanation перечислены формулы и символы, которые нельзя терять
- [ ] `termsToExplain` — все новые термины из `01`
- [ ] объём соответствует `targetLength` из brief
- [ ] `logs/planner.md`: на что опирался, что отбросил и почему
