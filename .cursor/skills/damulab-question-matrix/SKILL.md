# Damulab: проектировщик матрицы вопросов

Роль 2 пайплайна [damulab-question-pipeline](../damulab-question-pipeline/SKILL.md).
Смысл роли: **без матрицы генератор «рандомит»** — делает пять почти одинаковых
заданий на одно правило и один навык. Матрица — это распределение по навыкам, типам
и сложности, где каждый слот привязан к правилу или примеру из slice.

Формат артефакта — строго [contracts.md](../damulab-question-pipeline/contracts.md),
раздел `02-matrix.json`.

| Что | Где |
|-----|-----|
| Вход | `00-brief.json` (`count`, `typeMix`, `difficultyMix`, `illustrationPolicy`, `illustrationFor`) |
| Вход | `01-source-slice.json` (`rules`, `verbatimExamples`, `structuralExamples`, `generatorProfile`) |
| Выход | `02-matrix.json` (+ `typeMixPlanned`, `difficultyMixPlanned`, `slots[]`, `notes`) |
| Выход | журнал `logs/matrix.md` — почему такие навыки, типы и ловушки |

## Жёсткие правила

- число слотов **=** `brief.count`;
- распределение `type` по слотам **точно** равно `brief.typeMix`; `typeMixPlanned`
  копирует `brief.typeMix`; допустимы только `SCQ`, `MCQ`, `FILL_IN` (`MATCHING` — нет);
- `sourceRuleIds` **не пустой ни у одного слота** (`ruleId` из `slice.rules[]` с
  `role: "primary"`); если слот сделан от примера — дополнительно
  `sourceExampleRefs: ["p9#1"]` (`p{exactPage}#{номер задания}`), но правило всё равно указывается;
- у каждого слота заполнен `questionForm` из списка форм (см. ниже);
- заполнен блок `sourceQuality` (`sliceStatus` + `unverifiedRuleIds`);
- `localId` сквозные: `q01`, `q02`, … по порядку, без дыр — с ними сверяются `03` и `05`;
- слот не берёт материал вне slice; примеры с `usable: false` использовать нельзя.

## Реконструированные правила — рабочая опора, а не повод остановиться

Текста уроков в parsed нет, поэтому аналитик регулярно приносит правило с
`origin: "reconstructed"` и `ruleId` вида `RC_4501`. Для матрицы это **обычное правило**:

- слот на `RC_*` строится так же, как на `R004`; отказываться от работы или искать
  «обходные» слоты не нужно;
- зато обязательна пометка: `sourceQuality.sliceStatus` копируется из
  `slice.sliceStatus`, а все использованные `RC_*` перечисляются в
  `sourceQuality.unverifiedRuleIds`. Дальше это доезжает до `05` как
  `meta.sourceReliability: "unverified_reconstruction"`;
- в `notes` одной фразой: на каком правиле стоит пачка и что оно требует ручной сверки;
- правило с `role: "prerequisite"` (пришло со страниц соседней темы) в `sourceRuleIds`
  ставить **нельзя** — его место в `trapIdeas` как источник типичной путаницы.

Если `slice.sliceStatus: "blocked"` — матрицу не начинаем: это стоп на уровне оркестратора.

## Сколько слотов выдерживает срез

`slice.recommendedMaxCount` — не рекомендация «на глаз», а предел: при одном правиле и без
пригодных примеров 20 слотов неизбежно разъедутся в дубли навыка. Если
`brief.count` больше — не растягивай материал молча: скажи оркестратору, что нужно уменьшить
`count`, и напиши это в `logs/matrix.md`.

## Микс сложности

`difficultyMixPlanned` = `brief.difficultyMix`; если в brief `null` — дефолт
~20 % на 1–2, ~50 % на 3, ~30 % на 4–5 (например при `count: 12` → 1×1, 2×2, 6×3, 2×4, 1×5).

`difficulty` — **когнитивная нагрузка для этого класса**, не «сложность чисел»:

| Уровень | Что проверяет |
|---------|----------------|
| 1 | узнавание факта, прямой перенос из определения |
| 2 | применение правила в один шаг |
| 3 | выбор правила из нескольких или два шага |
| 4 | анализ, отсечение ловушек, перенос в новую ситуацию |
| 5 | синтез нескольких идей, нестандартная формулировка |

Не завышай уровень «для галочки»: длинные числа не делают задание уровнем 5.
Уровни 4–5 ставь только там, где slice реально даёт материал (несколько правил,
`structuralExamples` с двумя действиями, `word_problem`).

## Какой тип под какую задачу

| Тип | Когда уместен | Признак ошибки выбора |
|-----|---------------|-----------------------|
| `SCQ` | проверка одного решения или одного факта, есть 3 правдоподобные ловушки | правильный вариант очевиден без счёта |
| `MCQ` | в материале действительно **несколько** верных признаков / свойств («выбери все верные») | превратилось в «все варианты верны» или верен ровно один |
| `FILL_IN` | вычисление с однозначным числовым или коротким текстовым ответом (в т.ч. деление в столбик текстом) | ответ допускает несколько форм записи |

Держи и `generatorProfile.taskMixRecommended` из slice как ориентир по содержанию
(`calculation`, `word_problem`, `geometry`, `measurement`, `sets_logic`) — это про
характер задания, а не про тип вопроса.

## `questionForm` — чтобы пачка не читалась однообразно

`type` и `difficulty` не спасают от однообразия: при бедном срезе три слота легко выходят
одной формой «Вычисли: a · b». Поэтому у каждого слота есть явная форма задания, и матрица
раскладывает слоты по формам так же осознанно, как по навыкам.

| `questionForm` | О чём просят ученика | Пример постановки (без готовой формулировки) |
|----------------|----------------------|----------------------------------------------|
| `recall` | назвать правило, признак, термин | «какой следующий шаг правила» |
| `compute` | вычислить значение | «найти произведение» |
| `predict` | ответить **не вычисляя** | «сколько цифр будет после запятой» |
| `verify` | проверить чужой ответ, найти ошибку в готовом равенстве | «какие из равенств верны» |
| `restore` | восстановить пропущенное число или шаг | «какое число пропущено» |
| `compare` | сравнить два выражения или две записи | «какое произведение больше» |
| `word_problem` | бытовой сюжет с теми же числами | «масса шести пакетов» |
| `inverse` | обратная задача: дан результат, найти исходное | «при каком множителе произведение станет целым» |

Жёсткое ограничение: **не больше 2 слотов на одну `questionForm`** во всей пачке.
При `count: 12` это значит минимум 6 разных форм. Не хватает форм под материал — значит
`count` завышен относительно `recommendedMaxCount`, а не «надо повторить `compute` ещё раз».

Порядок набора при одном правиле: `recall` → `predict` → `compute` → крайние случаи записи →
`word_problem` → `verify` → `inverse`. Это тот же навык, но каждый раз другая мыслительная
операция, и заодно естественно растёт `difficulty`.

## `trapIdeas` — из типичных ошибок, а не случайные числа

`trapIdeas` — 2–4 коротких формулировки «какую ошибку повторяет дистрактор» по
**этому** правилу. Типичные ошибки, математика 5 класса:

- отсчёт координаты от 1, а не от 0 (координатный луч);
- потеря нуля в частном при делении в столбик (`306 : 3 = 12` вместо `102`);
- перепутаны делимое и делитель (или уменьшаемое и вычитаемое);
- порядок действий без скобок: считают слева направо, игнорируя умножение;
- в признаках делимости проверяют само число вместо суммы цифр (и наоборот).

Запрещено: «дистрактор = правильный ответ ±1» без объяснения ошибки.
Каждый `trapIdea` должен звучать как «ученик сделал X».

`skillFocus` — узкий навык («чтение координаты точки на луче»), `stemIdea` — одна строка
про сюжет задания **без готовой формулировки и без чисел ответа**.

## Иллюстрации

`needsIllustration` — **строго** по `brief.illustrationPolicy` / `brief.illustrationFor`.
Матрица не «улучшает» политику.

| `illustrationPolicy` | Поведение матрицы |
|----------------------|-------------------|
| `none` (дефолт) | у всех слотов `needsIllustration: false`, `illustrationReason: null` |
| `explicit` | `true` только у слотов из `brief.illustrationFor` (localId или условие) |
| `all` | `true` у всех слотов |
| `visual-topics` | `true` только там, где **без рисунка условие неполное**; причина — в `illustrationReason` |

Картинка **не нужна**: деление и умножение на 10, 100, 1000; деление на трёхзначные
«в столбик»; проценты «найди N % от числа»; порядок действий; простые уравнения без геометрии.

Картинка **уместна**: координатный луч, геометрическая фигура и её элементы, диаграмма,
условие «по рисунку», множества, угол/транспортир, развёртка — как в учебнике.
При `visual-topics` ставь `needsIllustration: true` **только** если без рисунка stem
неполный или сильно хуже; причину пиши в `illustrationReason`. Не «для красоты».

После `05` роль [damulab-question-illustrator](../damulab-question-illustrator/SKILL.md)
соберёт `06` + SVG. Импорт ассетов на сайт — отдельный будущий агент; матрица лишь
ставит флаги. При `none` везде `false`.

## Запреты

- Не писать формулировки заданий целиком и не давать варианты ответа — это [damulab-question-generator](../damulab-question-generator/SKILL.md).
- Не придумывать слоты без опоры на slice (нет правила — нет слота).
- Не «добирать» количество дублями одного навыка и одной формы: если правил мало, меняй
  `questionForm` и пиши это в `notes`.
- Не отказываться работать с `RC_*`-правилом и не «улучшать» его формулировку — правило
  принадлежит аналитику, матрица только помечает его в `sourceQuality`.
- Не менять `typeMix` из brief; не хватает материала на MCQ — это вопрос к оркестратору, а не тихая замена.
- Не ставить `subjectId` / `topicIds` / `gradeIds` и не использовать `MATCHING`.

## Чеклист перед сдачей `02-matrix.json`

- [ ] `schemaVersion: 1`, `runId` совпадает с папкой прогона
- [ ] `len(slots)` = `brief.count`; `localId` = `q01`…`qNN` без пропусков
- [ ] фактическое распределение `type` = `typeMixPlanned` = `brief.typeMix`
- [ ] фактическое распределение `difficulty` = `difficultyMixPlanned` (или дефолт 20/50/30)
- [ ] у каждого слота непустой `sourceRuleIds`, ссылки существуют в `slice.rules[]`
      и у всех этих правил `role: "primary"`
- [ ] `sourceExampleRefs` только на примеры с `usable: true`
- [ ] у каждого слота заполнен `questionForm`; ни одна форма не встречается больше 2 раз
- [ ] `sourceQuality.sliceStatus` = `slice.sliceStatus`, `unverifiedRuleIds` перечисляет все `RC_*`
- [ ] `brief.count` не превышает `slice.recommendedMaxCount` (или об этом сказано оркестратору)
- [ ] у SCQ/MCQ есть `trapIdeas`, каждая — описание конкретной ошибки
- [ ] `needsIllustration` соответствует политике; при `none` — все `false` и `illustrationReason: null`
- [ ] нет двух слотов с одинаковым `skillFocus` + `stemIdea`
- [ ] `notes` объясняет распределение; `logs/matrix.md` — решения и отброшенные варианты
