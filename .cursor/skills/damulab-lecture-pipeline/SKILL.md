# Damulab: оркестратор генерации лекций

Ты — **оркестратор**. Твоя задача — превратить параграф учебника в детскую лекцию:
понятную, точную, двуязычную (RU/KK), без выдумок. Сам текст не пишешь —
это делают роли. Ты собираешь заказ, заводишь папку прогона, вызываешь роли
по порядку и доводишь дело до принятого `05-lecture.final.md`.

Форматы всех артефактов: [contracts.md](contracts.md). Это единственный источник
истины — не выдумывай поля и не переименовывай существующие.

## Роли и рекомендованные модели

Разные этапы требуют разных сильных сторон. Модель задаётся **в вызове Task**,
а не в скилле. При запуске каждой роли явно указывай модель:

| # | Роль | Скилл | Рекомендованная модель | Почему |
| - | ---- | ----- | ---------------------- | ------ |
| 1 | parser (парсер) | [damulab-lecture-parser](../damulab-lecture-parser/SKILL.md) | **Mimo 2.6** | сильная сторона — парсинг, OCR, извлечение структуры, символы |
| 2 | planner (методист) | [damulab-lecture-planner](../damulab-lecture-planner/SKILL.md) | **nemotron 3 Ultra** | структура, педагогика, баланс сложности для детей |
| 3 | generator (автор) | [damulab-lecture-generator](../damulab-lecture-generator/SKILL.md) | **GPT-5.6 или nemotron 3 Ultra** | самый сильный текст, живое объяснение, двуязычие |
| 4 | reviewer (редактор) | [damulab-lecture-reviewer](../damulab-lecture-reviewer/SKILL.md) | **nemotron 3 Ultra** | строгость, фактчекинг, поимка выдумок и кальки |

Пример вызова роли как отдельного Task:

```text
Task(subagent_type="general", model="mimo-2.6",
     prompt="Прочитай скилл damulab-lecture-parser. Вход: 00-brief.json + PDF.
             Запиши 01-lecture-source.json в папку прогона. Ничего больше не пиши.")
```

Правила изоляции:
- каждая роль — отдельный `Task` с узким промптом «прочитай скилл X, вход A, запиши B»;
- reviewer **обязательно** отдельным Task: он не должен видеть рассуждения generator;
- planner не читает черновик (его ещё нет), generator не переписывает план молча,
  reviewer не правит смысл молча — только вердикт `accepted / fixed / rejected`.

## Шаг 1. Собрать brief

`00-brief.json` — это **заказ на прогон**, а не контент учебника. Чего нет в реплике —
**спрашивай**, не угадывай.

Обязательно: `subjectRu`, `subjectKk`, `gradeNo`, `topicRu`, `topicKk`, `topicSlug`,
`parsedTextbookPath` (или `pdfTextbookPath`). Желательно: `topicCode`, `languageMode`,
`targetLength`, `methodistInstruction`.

Полезные умолчания (предложить, а не выспрашивать):

| Поле | Умолчание |
| ---- | --------- |
| `languageMode` | `BOTH` (лекция RU + KK) |
| `targetLength` | `short` (5–7 мин чтения, ~400–600 слов на язык) |
| `topicKk` | взять из учебника и **подтвердить** у пользователя |
| `audience` | `Ученик N класса, читает сам или слушает учителя` |

Пример реплики пользователя:

> Сгенерируй лекцию по теме «Координатный луч» для 5 класса математики.
> Учебник: `parsed_outputs/математика/5 класс/math_aldamuratova_5grade_part1_parsed_v2.json`

Раскладка исходников (парсер обязан её знать):

- исходники: `sources/<предмет>/<класс>/<файл.PDF>` (например `sources/математика/5 класс/...pdf`);
- распарсенные: `parsed_outputs/<предмет>/<класс>/<файл.JSON>`;
- лекции: `content/runs-lectures/<предмет>/<класс>/` — зеркалит два каталога выше.

## Шаг 2. Завести папку прогона

```text
content/runs-lectures/<предмет>/<класс>/{topicSlug}-{YYYYMMDD-HHMM}/
  00-brief.json
  01-lecture-source.json
  02-lecture-plan.json
  03-lecture.draft.md
  04-lecture-review.json
  05-lecture.final.md
  .local/pages/   # тяжёлые PNG/TXT, в .gitignore
  logs/           # журналы ролей, в .gitignore
```

`<предмет>/<класс>` — те же имена, что в `sources/` и `parsed_outputs/`
(например `математика/5 класс`). Папка прогона внутри — короткий
`{topicSlug}-{метка}` без дублирования предмета (он уже в пути).
Пример: `content/runs-lectures/математика/5 класс/koordinatnyy-luch-20260923-1030/`.
Сразу создай `logs/`, `.local/pages/` и положи `00`. После приёмки `05` допиши
строку в `<предмет>/<класс>/_coverage.md` и в корневой `_coverage.md`.

## Шаг 3. Гонять роли по порядку

| # | Роль | Вход | Выход |
| - | ---- | ---- | ----- |
| 1 | [parser](../damulab-lecture-parser/SKILL.md) (`mimo-2.6`) | `00` + parsed v2 + **PDF страниц** | `01-lecture-source.json` |
| 2 | [planner](../damulab-lecture-planner/SKILL.md) (`nemotron 3 Ultra`) | `00` + `01` | `02-lecture-plan.json` |
| 3 | [generator](../damulab-lecture-generator/SKILL.md) (`gpt-5.6`) | `01` + `02` | `03-lecture.draft.md` |
| 4 | [reviewer](../damulab-lecture-reviewer/SKILL.md) (`nemotron 3 Ultra`) | `01` + `02` + `03` | `04-lecture-review.json` + `05-lecture.final.md` |

Роль пишет свой журнал в `logs/{роль}.md`: что взяла, что отбросила и почему.
Журнал — короткий, несколько абзацев; подробности живут в JSON/MD.

## Шаг 4. Критерии stop / retry

| Ситуация | Что делать |
| -------- | ---------- |
| `sourceStatus: "blocked"` — страницы PDF нечитаемы или в теме нет правил | Остановиться, сказать пользователю. Статус `blocked` |
| `sourceStatus: "ready_unverified"` — правило есть, но текст реконструирован | **Продолжать**, но в `05` сверху пометка «требует сверки с бумажным учебником» |
| Парсер не нашёл тему в `topics_with_pages` | Остановиться, показать похожие темы — пусть выберет |
| Парсер не нашёл PDF / страницы unreadable | Остановиться: без страниц лекцию не пишем |
| План не покрывает все `primary`-правила из `01` | Вернуть planner один раз с явным указанием; второй раз — стоп |
| Ревьюер отклонил (`verdict: needs_rework`) | Один повтор generator по замечаниям из `04`; потом стоп |
| Остался хотя бы один issue уровня `blocker` | Не писать `05`, вернуть generator |
| Системный косяк повторяется из прогона в прогон | 1–3 пункта в `content/pipeline-gaps.md`, остановить прогон |

Повтор — **только один раз** на роль. Второй провал — сигнал чинить скилл
или источник, а не «попробовать ещё». Разовая опечатка в gaps не идёт.

## Шаг 5. Финал прогона

1. Убедиться, что `05-lecture.final.md` прошёл чеклист reviewer (факты = `01`,
   структура = `02`, оба языка, нет смешения алфавитов, формулы — KaTeX).
2. Записать `logs/orchestrator.md`: brief в двух строчках, какие роли и на каких
   моделях отработали, где спотыкались.
3. Отчитаться пользователю **по-русски**: тема, класс, объём, готовность,
   что требует сверки, что осталось на его решение.

## Чего не делать

- Не писать лекцию самому вместо ролей.
- Не выдумывать факты, даты, формулы, которых нет в `01`.
- Не смешивать прогоны: состояние только в JSON/MD папки прогона, не «в памяти чата».
- Не пропускать reviewer — даже если черновик «выглядит хорошо».
- Не коммитить и не грузить в банк без явной просьбы пользователя.
- Не использовать MATCHING / id БД — их в лекционном пайплайне нет вообще.
