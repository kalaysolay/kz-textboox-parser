# Pipeline gaps — генерация вопросов

Живая память команды по мультиагентному пайплайну (люди + агент при доработках).
Это **не** «память роли» внутри прогона: журналы конкретного прогона живут в
`content/runs/{прогон}/logs/*.md`, разбор конкретных вопросов — в `04-review.json`.

## Как этим пользоваться

- **Перед правкой скиллов пайплайна сначала прочитай этот файл.** Скорее всего проблема,
  которую ты собрался чинить, уже описана — вместе с причиной, по которой её не чинили раньше.
- Оркестратор и ревьюер по итогам прогона **могут дописать 1–3 пункта** в «Открытые gaps»,
  если нашли **системный** косяк.
- Разовая опечатка в одном вопросе — не gap. Сюда попадает только то, что повторяется
  из прогона в прогон или упирается в архитектуру.
- Закрывая пункт, переноси его в «Закрытые» с датой и коротким «чем закрыли».

Формат пункта:

```markdown
- [ ] G00N / YYYY-MM-DD / роль (analyst|matrix|generator|reviewer|loader|pipeline) — заголовок
  - Симптом: что именно увидели, в каком прогоне
  - Гипотеза: почему так
  - Фикс: скилл / схема / скрипт / код
  - Приоритет: P0|P1|P2
```

    (`fill_numeric_mode_required`) и отклоняет нечисловой ключ в числовом режиме
    (`fill_numeric_answer_invalid`); единицы измерения остаются в тексте задания.

## Решения уже принятые (не переобсуждать без причины)

- Типы вопросов v1 — только **SCQ, MCQ, FILL_IN**. `MATCHING` в системе есть, но в пайплайне
  не используется: для предметного среза по учебнику он даёт слабую проверку понимания.
- `illustrationPolicy` по умолчанию — `none`. Картинки не угадываются, только по явной просьбе.
- **JSON-артефакты прогона — источник истины**, MD в `runs/*/logs/` — журналы ролей.
- Роли последовательные; ревьюер обязательно отдельным Task (изоляция от генератора).
- `05-questions.final.json` не содержит id БД и коммитится; всё машинозависимое — в `.local/`.
- Статичного `content/id-map.json` нет — отменён: он привязан к одной машине и разъехался бы
  между ноутами. Резолв id — ответственность человека/админки (или внешнего скрипта вне приложения).
- **Java seed удалён из платформы** (2026-08-04): нет `kz.damulab.seed`, нет Gradle
  `validateSeed` / `seedImport`, нет профиля `seed-import`. Импорт — через существующий
  админ-импорт банка вопросов. Валидация контракта — reviewer + чеклист seed; детерминированный
  валидатор при желании — отдельный репо/скрипт, **не** Spring.
- Темы автоматически не создаются. Не найдено или неоднозначно — стоп по этой теме.
- `content/runs/_coverage.md` отслеживает только генерацию. Статус загрузки в БД у каждой
  машины свой.
- Отдельного агента-переводчика в v1 нет: локализация — часть генератора и чеклиста ревьюера.
