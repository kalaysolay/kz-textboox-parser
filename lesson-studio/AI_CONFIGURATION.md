# Настройка CLI и модели в Мастерской уроков

Реализовано 28 октября 2026 года. Поддерживаются **Codex CLI** и **OpenCode CLI 2**. Один CLI и одна модель применяются ко всем пяти этапам урока. Профилей, автоматического выбора по предмету и отдельных моделей по ролям нет.

«ChatGPT CLI» здесь означает Codex с командой `codex`. OpenCode — другой исполнитель, внутри которого можно подключать разных поставщиков моделей.

Проверки: 88 автоматических тестов, реальный Codex с GPT-5.6 Sol High, реальный OpenCode с бесплатной Nemotron и OpenCode с локальным имитатором модели прошли. Реальный запрос к платной DeepSeek V4 Pro отклонён поставщиком из-за баланса. Подробности: [CLI-тесты](docs/AI_RUNTIME_TESTS_2026-10-28.md). При полной генерации по PDF Codex прошёл все пять этапов; Nemotron остановлена проверкой изменённых цитат. Короткий smoke не подтверждает пригодность модели для уроков. [Полная приёмка](docs/LESSON_E2E_2026-10-28.md).

## Быстрый старт

В PowerShell из папки приложения:

```powershell
cd D:\Projects\kz-textboox-parser\lesson-studio
Copy-Item ai.config.example.json ai.config.json
```

Команду копирования выполняйте один раз, если активного файла ещё нет. Затем редактируйте `ai.config.json`. Перезапускать сервер для изменения CLI или модели не требуется. Откройте заново окно «Новый урок», чтобы обновить показанную настройку.

Активный конфиг не создаётся при установке автоматически. Он исключён из Git и пакета выпуска; пример конфигурации входит в репозиторий.

## Codex / ChatGPT: GPT-5.6 Sol High

`D:\Projects\kz-textboox-parser\lesson-studio\ai.config.json`:

```json
{
  "runtime": "codex",
  "model": "gpt-5.6-sol",
  "reasoningEffort": "high"
}
```

Проверьте CLI и вход:

```powershell
codex --version
codex login status
```

Если вход не выполнен, используйте `codex login`. Для выбора другого точного ID и доступного уровня рассуждений откройте `codex` и вызовите `/model`.

Модель передаётся каждому этапу через `--model`, уровень — через `-c model_reasoning_effort="high"`. Глобальный конфиг Codex менять не требуется. Сохраняются `--ephemeral`, JSONL-прогресс, `workspace-write` и путь OCR для парсера. Запрошенный пример GPT-5.6 Sol High прошёл реальный файловый тест на этом компьютере; доступность в другом аккаунте зависит от аккаунта. [Настройки Codex](https://learn.chatgpt.com/docs/config-file/config-basic), [неинтерактивный запуск](https://learn.chatgpt.com/docs/non-interactive-mode).

## OpenCode: бесплатная Nemotron

Замените содержимое того же `ai.config.json`:

```json
{
  "runtime": "opencode",
  "model": "opencode/nemotron-3.5-lightning-free",
  "executable": "C:/Users/homepc/AppData/Local/Programs/OpenCodeCLI/opencode.exe"
}
```

Полный ID указанной пользователем модели в локальном каталоге OpenCode 2.2.0 — `opencode/nemotron-3.5-lightning-free`. Реальный файловый тест через адаптер прошёл: чтение скилла, точное сохранение RU/KK, SHA-256 и запись результата, около 86 секунд на этом компьютере. Это проверка интеграции, а не оценка качества готовых уроков. Доступ и лимиты бесплатных моделей проверяются при запросе; приложение не подменяет их другой моделью автоматически.

Для DeepSeek V4 Pro замените `model` на `opencode/deepseek-v4-pro`. В проверенном аккаунте эта платная модель вернула ошибку баланса; для неё нужно восстановить доступ к оплате.

Подключайте поставщика из корня репозитория, чтобы проверять доступ в том же проекте:

```powershell
cd D:\Projects\kz-textboox-parser
opencode
```

Внутри OpenCode:

```text
/connect
/models
```

Подключите поставщика и скопируйте точный ID выбранной модели. Для списка из терминала доступен `opencode models --standalone`. ID в поле `model` имеет вид `provider/model`; например, у OpenCode Go та же модель в проверенном каталоге называется `opencode-go/deepseek-v4-pro`. Доступ и оплата у поставщиков могут различаться. [Подключение поставщиков](https://opencode.ai/v2/docs/providers).

Если `opencode` не находится в PATH:

```powershell
& "$env:LOCALAPPDATA\Programs\OpenCodeCLI\opencode.exe" --version
```

Мастерская запускает `opencode run --standalone --format json --model ... --agent lesson-studio`, передавая длинное задание через stdin. На каждом этапе создаётся новая сессия, без истории автора для ревьюера. OpenCode может сохранять собственные сессии в своей локальной базе; его `--standalone` не означает `--ephemeral` Codex.

## Поля конфига

| Поле | Правила |
| --- | --- |
| `runtime` | Обязательно: `codex` или `opencode`. |
| `model` | Обязательно: точный ID. Для OpenCode — `provider/model` или `provider/model#variant`. Отображаемое название из интерфейса не подходит. |
| `reasoningEffort` | Необязательно, только для Codex. Принимаются `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`; фактическая поддержка зависит от модели. При отсутствии наследуется настройка CLI/модели. |
| `executable` | Необязательно: путь к программе или имя команды из PATH, без аргументов и внешних кавычек. Относительный путь разрешается от папки конфига. В JSON используйте `/` или двойные `\\`. |

Для OpenCode вариант рассуждений задаётся суффиксом `#variant` в `model`, если он поддерживается выбранной моделью. Например, формат `provider/model#high` допустим только при наличии варианта `high` в её каталоге. Поле `reasoningEffort` при OpenCode вызывает ошибку, а не игнорируется. [Модели и варианты OpenCode](https://opencode.ai/v2/docs/models).

Файл — обычный JSON: без комментариев, завершающих запятых, API-ключей, профилей и произвольных CLI-аргументов. Неизвестные поля, пустая модель и заполнители вроде `PROVIDER_ID/MODEL_ID` отклоняются до создания урока.

Путь к программе выбирается так: `executable` → прежний `LESSON_STUDIO_CODEX_EXE` для Codex → `codex` или `opencode` из PATH. Авторизация и ключи остаются в выбранном CLI; приложение не переносит их между инструментами.

## Когда применяются изменения

Мастерская читает конфиг перед созданием каждого заказа и при открытии каталога генерации. Настройки копируются в `00-Заказ.json` и локальное состояние `.local/jobs/<id>.json`. Только локальное состояние содержит путь к программе; ключи и полные конфиги CLI не копируются.

Изменение конфига влияет на **новые заказы**. Все этапы текущего заказа, повтор автора и кнопка «Продолжить» используют сохранённый CLI и модель, даже после перезапуска сервера или повреждения текущего конфига. Если сохранённая программа недоступна, нужно восстановить её по прежнему пути. Смена модели не служит неявным способом продолжить старый заказ.

Интерфейс показывает выбранные CLI, модель и заданный уровень. Это запрошенные параметры: приложение не утверждает, что поставщик подтвердил фактическую внутреннюю версию модели.

Без файла сохраняется прежнее поведение: Codex с моделью из локальных настроек CLI. Старые задания без снимка также продолжаются через Codex, независимо от нового конфига. Для них точная модель не зафиксирована; интерфейс сообщает об этом. Для явного управления новыми уроками используйте конфиг с `model`.

## Ошибки и доступ к инструментам

Ошибки конфига показываются в окне генерации и запрещают новый запуск. `--version` подтверждает наличие CLI, но не баланс, вход или доступ к модели. Эти ошибки могут возникнуть при первом запросе: заказ останется доступен для продолжения. По надёжным признакам отдельно показываются отсутствие CLI, недостаток средств, лимит, авторизация и недоступная модель. Неизвестная ошибка получает нейтральное сообщение. Автоматического переключения между CLI/моделями нет.

У OpenCode адаптер задаёт отдельного агента и разрешения для этапа: чтение репозитория, запись в каталог урока, необходимые локальные команды. CodeMode (`execute`) отключён: этапы используют прямые файловые инструменты и shell. Это устраняет наблюдавшееся зацикливание Nemotron во встроенной JavaScript-среде. Поиск разрешается исследователю, чтение внешних URL — исследователю и ревьюеру, когда заказ допускает дополнительные источники. Остальные инструменты и команды по умолчанию запрещены. `--auto` не используется.

Разрешённые `node`/`python` и другие локальные команды выполняются с правами пользователя; это **не песочница ОС** и не гарантия изоляции кода, запущенного внутри shell. Файловые правила OpenCode нельзя приравнивать к `workspace-write` Codex. Источники и скиллы должны быть доверенными; инструкции из внешних PDF/страниц не исполняются. [Разрешения OpenCode](https://opencode.ai/v2/docs/permissions).

Скиллы остаются в `.cursor/skills`: каждой роли передаётся абсолютный путь к нужному `SKILL.md`. Копировать их не требуется. `opencode.jsonc` при необходимости настраивает поставщиков и инструменты OpenCode; модель Мастерской явно передаётся из `ai.config.json`, независимо от модели по умолчанию OpenCode. Существующий `OPENCODE_CONFIG_CONTENT`, если задан, должен быть объектом JSON; адаптер дополняет его отдельным агентом.

Модель должна поддерживать необходимые инструменты и форматы входа. Выбор дешёвой модели сам по себе не гарантирует качество чтения PDF, фактов, RU/KK или поиска. Проверки структуры, бюджета, хеша и независимого ревью продолжают действовать.

## Как повторить тесты

Из `lesson-studio`, после установки обычных зависимостей приложения:

```powershell
node --test test/*.test.mjs tests/*.test.mjs
```

Тест настоящего OpenCode CLI с локальным имитатором модели, без платного API:

```powershell
node opencode-contract.mjs "C:/Users/homepc/AppData/Local/Programs/OpenCodeCLI/opencode.exe"
```

Короткие реальные запросы к моделям — они используют аккаунт выбранного CLI:

```powershell
node cli-smoke.mjs --runtime codex --model gpt-5.6-sol --reasoning-effort high
node cli-smoke.mjs --runtime opencode --model opencode/nemotron-3.5-lightning-free --executable "C:/Users/homepc/AppData/Local/Programs/OpenCodeCLI/opencode.exe"
```

Без аргументов `node cli-smoke.mjs` проверяет активный конфиг. Скрипты создают отдельные тестовые каталоги и отчёты в `.local/cli-tests/`, не изменяя учебные уроки. Реальный smoke проверяет чтение скилла и RU/KK, SHA-256, запись результата и неизменность входного файла. Полную генерацию урока по PDF и педагогическое качество он не подтверждает.

Те же команды доступны как `pnpm test`, `pnpm test:opencode-contract` и `pnpm test:cli` с соответствующими аргументами. Локальные отчёты не коммитятся; сводка проверенных результатов сохранена отдельно.

## Подготовка источника и проверка результата

Модель выбирается только через конфиг: ограниченного списка моделей в Мастерской нет. Укажите точный ID модели, доступной выбранному CLI. Профили и отдельные модели для ролей не нужны.

Для темы из каталога сервер готовит PDF, текст и изображения страниц; при непригодном текстовом слое автоматически использует локальный OCR и кеш. Язык распознавания берётся из учебника (rus/kaz, при неизвестном языке kaz+rus). Нужны существующие локальные языковые модели и зависимости content/tools.

Программа проверяет корректность JSON, структуру артефактов, ID урока, принадлежность PDF и страниц выбранному разделу. Итоговый урок также проходит проверку структуры, формул, заданного объёма и соответствия хеша ревью сохранённому файлу.

Содержательные правила находятся в инструкциях ролей. Исправление OCR, пересказ и восстановление порядка таблицы допускаются при сохранении смысла. Буквальное совпадение с OCR, список посимвольных замен и обязательные поля о визуальной проверке не являются условием продолжения. Правильность фактов, чисел и связей оценивает независимый редактор. Отличия от линейного извлечения записываются в «Проверка источника.json» как материал для его проверки, а не как автоматический запрет.

Парсер может честно оставить ограничения (ready_unverified/gaps): они передаются редактору. Если он выявит существенные ошибки, урок вернётся автору на исправление. Наличие или отсутствие инструмента просмотра PNG само по себе не ограничивает выбор модели; доступные инструменты и ограничения учитываются в промпте и ревью.

Заказы, остановленные прежними проверками цитат/OCR, можно продолжить кнопкой «Продолжить». Если сохранённый источник технически исправен, Мастерская использует его без повторного вызова парсера; содержательные замечания уйдут редактору. Повреждённый JSON и источник от другого PDF по-прежнему требуют исправления.

История OCR-приёмки: [отчёт](docs/OCR_ACCEPTANCE_2026-10-29.md). Описанные в нём прежние жёсткие ограничения отменены этой доработкой.
