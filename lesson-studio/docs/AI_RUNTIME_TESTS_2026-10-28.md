## Реальный OpenCode и Nemotron

CLI: `opencode v2.2.0`. Модель пользователя найдена в каталоге с полным ID `opencode/nemotron-3.5-lightning-free`.

```powershell
node cli-smoke.mjs --runtime opencode --model opencode/nemotron-3.5-lightning-free --executable "C:/Users/homepc/AppData/Local/Programs/OpenCodeCLI/opencode.exe"
```

Итоговый результат: **PASS**, все четыре проверки. Настоящая модель прочитала скилл и входной файл RU/KK, записала `result.json`, точно сохранила обе строки и вычислила верный SHA-256. Входной файл не изменён. Запуск занял около 86 секунд и завершился самостоятельно с кодом 0. Другая модель не использовалась.

Первый запуск был остановлен по таймауту 180 секунд. При диагностике обнаружились две особенности интеграции:

- Короткий запрос успешно возвращал `OK`, но OpenCode не отправлял `step_finish`. Адаптер теперь принимает финальный `text` с `time.end` при чистом завершении и отсутствии ошибки; это покрыто регрессионным тестом.
- В файловом тесте Nemotron многократно использовала `execute` (CodeMode), не вызывая нужные файловые инструменты. Этот диагностический запуск остановлен. У агента Мастерской CodeMode отключён через разрешения, остаются прямые инструменты. После изменения полный файловый smoke прошёл за 86 секунд при лимите 180 секунд.

В `cli-smoke.mjs` добавлены фиксированные подписи прогресса и время последней активности; сырой вывод и рассуждения модели не сохраняются в отчёт. Сообщение о таймауте теперь имеет приоритет над общей ошибкой процесса.

## Настоящий OpenCode CLI с локальным имитатором модели

CLI: `opencode v2.2.0`.

```powershell
node opencode-contract.mjs "C:/Users/homepc/AppData/Local/Programs/OpenCodeCLI/opencode.exe"
```

Результат: **PASS**, девять проверок, в том числе при повторном запуске после изменений для Nemotron. Настоящий CLI подключился к локальному OpenAI-совместимому HTTP-серверу. Только ответы модели задавались тестом; файловые инструменты, shell и проверки разрешений выполнял сам OpenCode:

- прочитан текст RU/KK и скилл из соседнего каталога внутри репозитория;
- разрешённая команда вычислила SHA-256;
- результат записан в каталог тестового урока;
- запрещены абсолютная и относительная записи за пределы каталога урока;
- запрещены неразрешённая shell-команда и чтение файла вне репозитория;
- входной файл остался неизменным.

Тест учитывает повторный запрос модели при старте CLI: имитатор определяет следующий шаг по истории разговора, а не по числу HTTP-запросов. Тест не требует действующего платного ключа и ничего не утверждает о качестве DeepSeek.

## Реальные запросы OpenCode к DeepSeek V4 Pro

Проверены `opencode/deepseek-v4-pro` и `opencode-go/deepseek-v4-pro`.

Оба ID присутствуют в локальном каталоге. Оба запроса отклонены поставщиком: `provider.quota`, HTTP 402, недостаточно средств. Адаптер вернул `ai_quota` и понятное сообщение о балансе. Переключения на другую модель не произошло, сырые ответы и ключи не попали в состояние Мастерской.

Отдельная проба бесплатной `opencode/deepseek-v4.1-flash-free` вернула `provider.free-limit`, HTTP 429. Это ограничение аккаунта, а не подтверждение генерации.

**Успешную работу реальной DeepSeek V4 Pro пока не подтверждаем.** После восстановления доступа следует повторить `cli-smoke.mjs` с её ID, затем выполнить полноценную генерацию короткого тестового урока по учебнику.
